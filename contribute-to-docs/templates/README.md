# Documentation templates

Choose a template by the reader's purpose. This catalog routes authors; it is not a tutorial. Start with the [page contracts and review checklists](../what-to-contribute/creating-new-docs.md#content-types).

| Reader purpose | Template |
| --- | --- |
| Guided learning along one chosen route | [Tutorial](template-tutorial.md) |
| Accomplishing a bounded goal | [How-to guide](template-procedure.md) |
| Looking up exact fields, defaults, and constraints | [Reference](template-reference.md) |
| Understanding behavior, relationships, and trade-offs | [Explanation](template-concept.md) |

The old Procedure and Concept filenames are retained to preserve links; their contracts are how-to and explanation respectively.

## Related formats

- [Troubleshooting how-to](template-troubleshooting.md): symptom, evidence, conditional remedy, and verification.
- [Blog entry](template-blog-entry.md): publication guidance outside the four technical documentation modes.

For a **landing page**, use a short introduction and a few concrete destination links with accurate descriptions. Do not use a lesson scaffold or `function: tutorial` for an index, catalog, or next-steps page. A routing-only page can omit `function`; do not invent a fifth value.

The front matter inside each technical scaffold is an example for versioned pages. Select the actual audience and components. Remove author prompts, empty sections, and irrelevant properties before submitting.
